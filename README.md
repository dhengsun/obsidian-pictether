# Pictether

Obsidian Desktop 的轻量级外部附件插件。附件保存在本地，S3 兼容对象存储用于后台备份和恢复，已接入 Cloudflare R2。

当前为开发测试版。自动化验证与实机验收分别记录在 [验证记录](docs/validation.md)。本轮设置页、SQLite 每日统计升级及重置流程仍待用户实机验收；其他 S3 服务需分别验证兼容性。

## 功能

- 粘贴、拖入或选择图片、视频、PDF。
- Vault 外统一存储，使用稳定的 `mdasset://` 引用。
- 阅读视图、实时预览、图片预览、视频播放、PDF 翻页。
- OSS 自动备份、重试、校验与缺失附件恢复。
- RK 凭据列表、弹窗连接测试及灰／红／绿状态，今日备份数字概览。
- SQLite 备份记录及旧状态迁移、每日统计和显式确认的本地重置。
- 单篇笔记和附件打包导出为标准 Markdown。

JSON、Markdown 的新导入由 Obsidian 原生处理。JSON 附件管理已移除：旧受管文件和笔记保留，但旧 `mdasset://` JSON 引用不再由插件解析；不会自动迁移进 Vault。此前受管的 Markdown 文件保留兼容读取。

## 支持格式与存储

- 图片：PNG、JPG/JPEG、WebP、GIF、BMP、AVIF、SVG。
- 视频：MKV、MOV、MP4、OGV、WebM。容器识别不保证所有视频编码可播放。
- PDF：按页渲染，支持翻页。

默认附件根目录为当前用户主目录下的 `Pictures/markdown-assets`，可在设置中修改。布局为：

```text
{root}/{namespace}/{YYYY-MM-DD}/{HHmmss-xxxxxx}.{ext}
```

日期和时间取导入时的本地时间，随机部分为六位小写十六进制。独占写入并重试名称碰撞；旧 UUID 文件名继续可读。仓库名直接显示 Obsidian 的系统名称，已有附件路径沿用保存的命名空间，改名不搬迁文件、不改写引用。同一命名空间允许不同设备使用，不再设置设备归属锁；旧归属记录不参与检查。路径安全校验及本地/云端防覆盖机制保留。

```markdown
![Attachment](mdasset://my-vault/2026-10-29/120000-abcdef.png)
```

引用不写入机器绝对路径。插件验证真实路径、符号链接、媒体内容与扩展名；SVG 只作为图片加载，不注入页面。附件导入、摘要、导出、云传输使用流式处理。插件不会自动删除用户附件、覆盖已有附件或向云端同步删除。

## 开发与安装

开发需要 Node.js 24+、npm；打包需要 Python 3。无需全局依赖。

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run package
```

将 ZIP 内 `pictether` 文件夹放到 Vault 的 `.obsidian/plugins/`，或复制 `main.js`、`manifest.json`、`styles.css` 到 `.obsidian/plugins/pictether/`，再自行启用插件。仅支持桌面，最低 Obsidian API 版本 1.11.4；SQLite 另外要求实际运行环境提供 `node:sqlite`。不需要 `sqlite-worker.cjs`，旧文件即使保留也不会加载。

设置保存后自动安全切换运行配置，无需反复重载插件。改变根目录不会搬动旧附件；仓库名自动从 Obsidian 获取。仅需本地功能时，无需配置 OSS。

## 设置与命令

设置分为通用设置、OSS 配置、备份与恢复、今日概览四区。通用设置只有附件根目录和仓库名。OSS 配置包含服务地址、存储桶和 RK 列表，签名区域放在折叠的高级设置内。

点击加号新增，或在 RK 右侧三个点菜单中选择“编辑”，在弹窗内输入名称、Access Key ID、Secret Access Key，可测试连接、保存或取消。不需要 Token value。列表只显示脱敏黑点；灰色为未测试，红色为测试失败，绿色为测试成功。修改地址、桶、区域或凭据后旧结果失效。多组 RK 中仅“当前”一组用于备份，失败时不自动轮换。

凭据保存在 SecretStorage，配置中仅保存引用名称。编辑时密码框留空可沿用原值；替换时同时填写两项。测试草稿及取消不修改正式配置，已有密钥不回显。SecretStorage 不能视为插件间的安全隔离。

提供命令：

- Insert Attachment
- Restore Missing Attachments
- Export Note with Attachments

OSS 使用私有 Bucket，不要求公开域名。正常读写优先本地，网络失败不应妨碍本地插图；上传任务保留并重试。冲突对象不自动覆盖。恢复先校验再排他发布，不覆盖已有文件。

开启“自动备份”后，会发现当前命名空间的已有附件，并自动处理后续导入及失败重试；不提供立即备份按钮。关闭时活动任务安全结束，待处理记录保留。本地缺失时自动恢复，也可点击“恢复缺失附件”批量补齐。连接测试只列出最多一个对象，不产生测试文件，不代表验证了上传权限。

今日概览按本地日期、当前根目录和 OSS 目标统计“备份次数、成功、冲突、失败”。一次附件备份尝试计一次，重试另计；连接测试和恢复不计入该面板。数字跨重载保留，从本轮升级开始记录，不推算历史。

“重置插件”会删除**当前附件根目录下所有命名空间的受管理附件**，并清空配置、全部任务、统计、旧插件状态备份及插件管理的密钥值。共用该目录的其他库附件也在范围内；未备份附件删除后无法恢复。笔记和云端对象保留，笔记引用会暂时缺失，重新配置 OSS 后可恢复已备份附件。历史上曾用但当前未配置的根目录不自动清理。

确认窗展示实际目录、命名空间和附件数量，须勾选确认。插件等待活动操作结束，重新检查范围后才删除；文件变化则要求重新确认。只删除识别出的受管理文件和插件元数据，不递归删除根目录；不明文件保留并提示，符号链接和危险目录拒绝处理。失败时保留“继续重置”状态及原目录设置。数据库初始化标记保留，避免旧记录重新导入。Obsidian 公开 API 只能清空密钥值，宿主凭据列表可能保留空条目；不清理无法确认归属的共享凭据。

当前重置范围见 [归属与重置方案](docs/namespace-reset-plan.md)，历史设置设计见 [设置页重构方案](docs/settings-redesign-plan.md)。

导出创建独立目录，重写受管引用为 `assets/` 相对路径，去重并处理同名附件。原笔记不变；缺失受管附件会报错。未完成的导出保留 `EXPORT-INCOMPLETE.txt` 标记，不静默报告成功。普通 Markdown 工具和多数 AI 工具不能直接读取 `mdasset://`；应使用导出结果或独立路径解析模块。

## 记录与可靠性

`data.json` v2 只保存设置，备份记录存于插件目录的 `pictether.sqlite`。SQLite 在插件进程内按条访问，使用 WAL、FULL 同步、索引和事务；异步接口串行执行，大批迁移、清理、校验和统计分批让出事件循环。单次 SQLite 调用仍同步，磁盘延迟或首次旧 JSON 解析可能造成短暂停顿，不能保证完全无阻塞。

首次迁移会原样保留 `data-v1.<SHA256>.backup.json`，再在事务中导入、校验并提交迁移标记。副本通过暂存文件同步后排他发布，避免中断留下半份正式备份。中断可重试，清理记录后不会从旧副本自动重新导入。已退出支持范围的旧附件记录作为元数据保留，同步时会标记为冲突，不再读取其文件或访问云端。

SQLite schema v2 增加每日聚合统计；旧任务保留，完成／失败的修订检查与计数原子提交。旧单组凭据自动转为列表中的“默认凭据”，沿用原引用，初始状态为未测试。

数据库、模块或迁移出错时保留旧数据，本地读取、导入和导出仍可使用；备份停用，设置暂不保存以保护原始记录。缺失的 v2 数据库不会被静默重建。记录提交与外部附件发布不是跨文件事务；记录写入失败时会提示，修复后重新启用自动备份会重新发现附件。

请备份本地附件、设置和数据库。WAL 模式下不能把正在使用的主数据库文件单独复制视为完整备份；应停用插件并等待连接关闭后复制，或使用 SQLite 一致性备份工具。当前不支持数据库的跨设备实时双向同步。

移动端、压缩/OCR、图库、孤立附件清理、自动同步删除、多云和旧附件批量迁移不在当前范围。
