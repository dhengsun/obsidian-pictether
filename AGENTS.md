# Pictether engineering rules

## Scope and safety
- Desktop-only Obsidian plugin; TypeScript, local-first external attachment storage.
- Only generate and parse `mdasset://namespace/YYYY-MM-DD/HHmmss-xxxxxx.ext` (local time, six lowercase hexadecimal random digits). User explicitly removed mdimg compatibility; outside the confirmed reset exception, do not migrate or delete old files/references. UUID-v4 filenames remain safe to parse under mdasset.
- Retry generated-name collisions with exclusive file publication; never overwrite. Support PNG, JPEG, WebP, GIF, BMP, AVIF, SVG; MKV, MOV, MP4, OGV, WebM; PDF. JSON and Markdown imports belong to Obsidian: never intercept `.json` or `.md`, even with a misleading MIME, and do not advertise them in the picker. Preserve existing managed MD references/records for reading without adding new imports. Normalize JPEG to `.jpg`. Audio/HEIC/TIFF are outside current support.
- JSON attachment management has been removed by user request (2026-10-29): no content validator, managed reference, rendering, export or cloud recovery for JSON files. Preserve existing files, notes and opaque backup metadata; unsupported old record types must not prevent migration or trigger file/network reads. Existing managed Markdown files remain readable only as legacy attachments. Open attachments via public Electron shell.openPath after revalidating the managed path; never hand app resource URLs to the OS. Native widget cleanup must restore source attributes even when temporarily detached. Export as ordinary links.
- Clear Backup Records clears only current-root task records after active uploads settle, preserves concurrently created jobs, and never deletes attachments or cloud objects. Warn that note references can still trigger recovery and manual sync can rediscover files.
- SVG is displayed only as an image resource, never injected as page markup. Validate formats by contents, not extension alone. Container support does not imply every video codec is decodable.
- Stream attachment import, hashing, export, cloud transfer and recovery. Read bounded metadata to identify media. Video/PDF playback uses verified local resource URLs, not full-file in-memory blobs.
- Never overwrite existing attachments or propagate deletions to OSS. User approved (2026-10-30) confirmed UI reset deleting all managed local attachments across all namespaces in the current assets root; never execute real reset during development. Other file deletion still requires authorization.
- Never put credentials in source, fixtures, logs, Git, or exported notes.
- Ask before deleting files/directories/history, editing credentials/.env/CI, schema migrations, pushing/rebasing/resetting Git, installing global dependencies, or publishing.
- Prefer public Obsidian APIs. Do not claim real-app or real-cloud verification from unit tests.

## Structure and naming
- Root: plugin manifest/version compatibility map, package/build/type/test configuration, build/package/license scripts, README, MIT LICENSE, CONTRIBUTING.md, SECURITY.md, CHANGELOG.md, generated THIRD_PARTY_NOTICES.md and this file. `licenses.mjs` collects installed runtime dependency licenses; package generation refreshes notices and includes them with LICENSE. `docs/releasing.md` is the manual GitHub release checklist. Never create/edit CI workflows or push/publish without separate authorization. Default assetsRoot derives from the current user's home, never a developer-specific absolute path.
- `src/core/`: UI-independent references, image validation, filesystem storage, queue, backup, export. Use kebab-case filenames and named exports.
- `src/core/assets.ts`: common media type policy/content detection; `src/obsidian/pdf-preview.ts`: lazy PDF.js canvas viewer using public `loadPdfJs`. Existing image-specific module names may remain as compatibility exports while being generalized; do not delete files as part of refactoring.
- `src/obsidian/`: settings, import integration, Reading View and CodeMirror rendering. `file-decorations.ts` retains the measurable native image proxy for media previews; JSON-specific source spacers and their registrations are removed. Preserve native controls and keep previews compact. The user performs Obsidian interaction/testing; the agent edits code and runs automated checks only.
- Settings use four sections: general, S3-compatible OSS, backup/recovery, and today's aggregate metrics. `credentials.ts` manages the RK list and `credential-dialog.ts` owns its modal. One RK is active; test results are bound to endpoint/bucket/region/reference identity. Draft tests and cancellation never change saved configuration. Password fields never prefill stored values. New secret pairs use `pictether-oss-<uuid>-id/key`; retain compatibility with `pictether-r2-<uuid>-id/key`. Normal saves never overwrite/delete secrets. Explicit confirmed RK deletion/reset may remove exclusively plugin-generated entries, never unrelated/shared arbitrary names.
- User approved (2026-10-29) settings conversion from a legacy pair to a credential list and SQLite schema v2 adding daily backup-attempt aggregates. Keep existing tasks and migration markers; daily counts begin at this upgrade and use local dates, root and target. Complete/fail revision checks and counters commit atomically. `data.json` remains settings-only and never contains secret values.
- User approved revised reset (2026-10-30), superseding the earlier attachment-preserving reset: clear configuration, all jobs/statistics, plugin-owned credentials/state backups, and all recognized managed attachment files across all namespaces in the currently configured root. Preserve notes, cloud objects, unknown files, and unconfigured historical roots. Clean recognized claim/staging files and empty managed directories, never recursively delete the root. `reset.ts` owns bounded scans, identity-bound review snapshots, path protections and selective cleanup. Reject filesystem/home/Vault/plugin roots, Vault ancestors/descendants, symlinks and nonregular managed entries. Confirmation shows root, namespace/file counts and unknown entries, warns shared-root impact and irreversible unbacked-file loss, and requires explicit acknowledgement. Rescan after quiescing; changed review scope requires new confirmation before deleting. Keep resetPending/root/config durable until all required stages succeed; partial cleanup remains retryable. Keep initialized database marker to prevent legacy reimport. Only exact regular-file `data-v1.<sha256>.backup.json[.<uuid>.staging]` matches inside the plugin directory may be removed. SecretStorage has no public deletion API: clear owned values via setSecret; unrelated/shared arbitrary names remain. Do not execute reset or delete real user secrets/attachments during development; only explicit UI confirmation triggers it.
- `src/main.ts`: plugin composition and lifecycle only.
- `tests/`: `*.test.ts`, generated fixtures stay in OS temporary directories.
- `docs/`: architecture, development progress and manual acceptance checklist.
- Generated root `main.js`, `pictether-*.zip`, `node_modules/`, coverage and local plugin data are ignored. Do not create ad hoc permanent scratch directories. Cleanup requiring file deletion needs user permission.
- External assets: `{root}/{namespace}/{date}/{HHmmss-xxxxxx}.{ext}` for new imports; legacy UUID names coexist. Multiple devices/Vaults may share a namespace; never compute/check device/inode ownership or create namespace claims. Existing claims are inert compatibility files, untouched outside confirmed reset. `.pictether/` retains managed staging files. No image folder inside the vault. Display the system Vault name read-only; retain the saved namespace for stable historical paths and default new ones from the Vault name.
- Plugin state: `data.json` v2 stores settings only; `pictether.sqlite` stores backup jobs, daily aggregates and migration metadata. `job-store.ts` provides a serialized async interface over in-process node:sqlite; Obsidian's renderer reports ERR_MISSING_PLATFORM_FOR_WORKER, so do not use Node workers. Large migration/verification/clear/count operations run in bounded batches and yield to the event loop. Single SQLite calls are synchronous and their latency must be measured, not assumed nonblocking; use a short busy timeout. `sqlite-worker.ts` is retained only as an obsolete source marker and is not built/shipped. The execution-mode change itself needed no schema change; the separately approved statistics upgrade uses schema v2. Use WAL/FULL, bound parameters, indexes and revision checks. JSON-state migration remains authorized: preserve an exclusive hash-named backup, validate generic safe legacy record keys, import atomically and idempotently, and never reimport cleared records. Outside explicit confirmed reset, never delete old backups/files; never silently revert job persistence to JSON. Database/module/migration failure preserves JSON and local attachment reading/import/export. Credentials stay in SecretStorage.

## Verification
- `npm run typecheck`
- `npm test`
- `npm run build`
- Run all three after each development step. Add meaningful regression tests for reference/path security, exclusive file publication, shared namespaces, queue crash recovery/conflicts and export preservation.
- Record manual Obsidian/R2 checks in `docs/validation.md`, distinguishing pending from passed.
- `npm test` builds the shipped bundle first; retain the CommonJS loader regression test. Import host-provided Obsidian APIs statically so the plugin never depends on Node ESM resolution of `obsidian`.
- Change these conventions before introducing a new directory or persistence convention.

## Runtime temporary files
- Atomic image writes use `.pictether/staging/` and remove only their own staging link after publication. Interrupted staging files remain for manual inspection.
- Legacy-state backups are written/synced to unique `<backup>.<uuid>.staging` files in the plugin directory, then published with an exclusive hard link. Runtime removes only its own staging link; interrupted staging files and existing backups remain untouched.
- Exports use an `EXPORT-INCOMPLETE.txt` marker until all output files succeed; runtime removes only this generated marker on success.
- Generated isolated manual test vaults live in OS temporary directories. The user-created `插件测试/` vault is also permitted for manual acceptance; it includes its own AGENTS.md, is Git-ignored, and the plugin is never enabled automatically.
- `.test-assets/` is the optional manual-test attachment root outside the test vault, follows the external asset structure above, and is Git-ignored. Test notes/assets are never automatically deleted.
